## About me

I'm **Saravan Kumar**, a **Software Engineer and AI Engineer** and currently a **Founding Engineer at Varpitech**. I work across product development, full-stack software engineering, AI integration, and the infrastructure needed to bring applications together.

My current work includes developing an **AI-powered recruitment platform** as a deployed pilot and building an independent **desktop software product**. Beyond these, I experiment with developer tooling, repository understanding, incident-response systems, and algorithmic optimization. I enjoy working on problems that require connecting the product experience to the underlying APIs, data models, AI workflows, and deployment architecture.

I follow a **spec-driven development** approach: define the problem and intended behavior, make architectural decisions, implement iteratively, and validate the result. AI-assisted development is part of my workflow, alongside code review, testing, debugging, and integration work.

## What I'm building and exploring

Rather than treating every repository as a finished product, I work across a mix of **deployed pilot software, active builds, and technical experiments**.

- **AI-enabled business applications:** Integrating application workflows with LLM-assisted analysis, retrieval, ranking, and structured decision support.
- **Desktop product engineering:** Exploring local-first application design, data management, desktop UX, and optional on-device AI capabilities.
- **AI-assisted developer tools:** Investigating how software repositories can be analyzed and explained through retrieval and contextual reasoning.
- **Incident-response workflows:** Exploring how diagnostic steps, tool integrations, and agent orchestration can support software troubleshooting.
- **Algorithms and performance:** Experimenting with graph algorithms, learned components, benchmarking, and performance comparisons.

The repositories contain different stages of work. A working prototype, tested implementation, and production deployment are not the same thing, and I aim to keep that distinction clear.

## How I approach engineering

```text
Problem and requirements
        |
        v
Specification and expected behavior
        |
        v
Architecture and trade-offs
        |
        v
Implementation and integration
        |
        v
Testing, debugging, and evaluation
        |
        v
Deployment, feedback, and iteration
```

I use AI-assisted coding tools within this process, but the objective is not simply to generate code. It's to build a coherent system: interfaces connected to real APIs, APIs connected to persistent data, AI features supplied with appropriate context, and behavior that can be tested and explained.

I am particularly interested in **backend architecture, AI application engineering, system integration, and building maintainable products**. I also value understanding the trade-offs behind a technical choice rather than adopting a framework just because it is popular.
